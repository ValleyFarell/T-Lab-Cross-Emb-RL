# H-goal-EuR: выбор полного состояния около цели

## Интуиция

Одна и та же точка `(x,y)` соответствует многим физическим состояниям: робот может стоять под разными углами, иметь разные скорости и находиться в разных фазах шага. Метод проверяет, влияет ли выбор такого полного состояния на то, насколько уверенно агент попадает в цель.

## Мотивация

Если исходное целевое намерение усредняет слишком разные состояния, робот может приблизиться к цели, но начать кружить вокруг неё. Выбор более подходящей позы около той же точки способен изменить управление без изменения самой задачи.

## Математика в трёх предложениях

Для реального состояния `w` возле цели строится `z_w = normalize(B(w))`. Каждый участник ансамбля оценивает `v_e = ⟨F_e(s,z_w),z_r⟩`, а итоговый балл равен `mean(v_e)-λ[max(v_e)-min(v_e)]`. Выбирается состояние с наибольшим баллом; при двух оценщиках и `λ=0.5` это ровно меньшая из двух оценок.

## Вариант 1: синтетическое состояние

```text
целевое_состояние = [координаты_цели, текущее_состояние[2:]]
намерение = normalize(B(целевое_состояние))
```

Координаты заменяются целевыми, а ориентация, скорости и остальные признаки копируются из текущего состояния. Это эвристика: полученное состояние может отсутствовать в распределении офлайн-данных.

## Вариант 2: реальное офлайн-состояние

$$
v_e(s,w)=\langle F_e(s,\operatorname{normalize}(B(w))),z_r\rangle,
$$

$$
S(s,w)=\operatorname{mean}_e v_e(s,w)
-\lambda\left[\max_e v_e(s,w)-\min_e v_e(s,w)\right].
$$

Выбираются только реальные обучающие состояния внутри `candidate_radius` вокруг неизменной цели. Представление `z_r` остаётся справа в скалярном произведении; `B(w)` задаёт именно намерение политики.

## Запуск обоих вариантов

```powershell
python -m scripts.run_h_goal_eur `
  --variant synthetic-current `
  --task-id 1 `
  --environment-seed 0 `
  --controller-seed 0 `
  --temperature 0 `
  --results-dir results_h_goal_eur_synthetic
```

```powershell
python -m scripts.run_h_goal_eur `
  --variant dataset-max-v `
  --task-id 1 `
  --environment-seed 0 `
  --controller-seed 0 `
  --temperature 0 `
  --hge-replan-interval 1 `
  --hge-candidate-radius 0.5 `
  --hge-max-candidates 64 `
  --hge-disagreement-penalty 0.5 `
  --results-dir results_h_goal_eur_dataset
```

`--variant` выбирает способ построения состояния; `--hge-replan-interval` задаёт число шагов между обновлениями; `--hge-candidate-radius` — радиус поиска; `--hge-max-candidates` — максимальное число состояний; `--hge-disagreement-penalty` — коэффициент `λ`.

## Ограничения

Метод не строит последовательность промежуточных целей и поэтому не подменяет основной многоточечный планировщик. Высокая FB-оценка не является доказанным расстоянием по лабиринту и должна проверяться по реальному успеху и числу шагов.

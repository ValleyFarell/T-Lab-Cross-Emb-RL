# Правила объективного сравнения

## Интуиция

Новый метод может выглядеть быстрым просто потому, что справился лишь с наиболее лёгкими случаями. Поэтому сначала сравнивается доля успешных эпизодов на одинаковых сценариях, а число шагов — только там, где оба метода дошли до цели.

## Что должно совпадать

Для корректной пары должны совпадать задача, фактические координаты старта и цели, `environment_seed`, `controller_seed`, температура и чекпоинт. Повторный запуск тех же параметров не становится новым независимым наблюдением.

## Главная метрика

$$
\text{Доля успехов}=
\frac{\text{число успешных эпизодов}}
{\text{общее число сопоставимых эпизодов}}.
$$

Её нужно приводить суммарно и отдельно по задачам.

## Дополнительные метрики

- Число шагов и длина маршрута — только на общих успехах.
- Итоговое расстояние до цели — на всех сопоставимых эпизодах.
- Частота падений и поведение у цели — как объяснение причин неудач.
- Доверительные интервалы и точный тест Мак-Немара — как оценка неопределённости.

Разности определяются как «новый метод минус исходный». Положительная разность успехов полезна, отрицательная разность шагов означает более быстрый проход.

## Запуск сравнения

```powershell
python -m scripts.paired_analysis `
  --baseline-dir results_baseline `
  --candidate-dir results_candidate `
  --output comparisons/candidate_vs_baseline.json `
  --bootstrap-seed 0 `
  --bootstrap-samples 10000
```

`--baseline-dir` задаёт каталог исходного метода, `--candidate-dir` — нового, `--output` — файл результата. `--bootstrap-samples` определяет число повторных статистических выборок, а `--bootstrap-seed` делает их воспроизводимыми.

Если обнаружены дубликаты или разные значения `controller_seed`, сравнение нельзя считать полностью парным.

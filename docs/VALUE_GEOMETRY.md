# Проверка геометрии замороженной FB-ценности

## Интуиция

Полное состояние робота содержит положение, ориентацию, скорости и признаки движения суставов. Однако на большом расстоянии до цели может оказаться, что замороженная оценка ценности в основном определяется тем, где находятся старт и цель на карте. Эксперимент проверяет, действительно ли сложное состояние можно заменить двумя или четырьмя информативными координатами.

## Мотивация

Если качество маршрута хорошо предсказывается в пространстве меньшей размерности, планирование нескольких подцелей становится проще. Но это гипотеза о конкретном обученном FB-критике, а не заранее установленный физический закон: возле цели поза и скорость робота могут снова стать важными.

## Математика в трёх предложениях

Замороженный критик задаёт значения `Y(s,g)`, которые используются как обучающие метки без изменения `F` и `B`. Сравниваются модели `H_xy(x_s,y_s,x_g,y_g)`, `H_full(s,g)` и `H_d(E_d(s),E_d(g))`, где `E_d` сжимает состояние до `d` чисел. Если сжатая модель хорошо воспроизводит `Y`, отдельно проверяется, можно ли восстановить из её координат реальные `(x,y)`.

## Что именно предсказывается

Для режима `--target-mode xy-goal`:

$$
z_g=\operatorname{normalize}(B(g)),
\qquad
q=g[:2],
$$

$$
v_e(s,g)=\langle F_e(s,z_g),z_q\rangle,
$$

$$
Y(s,g)=\operatorname{mean}_e v_e
-\lambda\bigl[\max_e v_e-\min_e v_e\bigr].
$$

`z_q` строится для пространственной награды около координат `q`. При двух оценщиках и `λ=0.5` итоговое значение равно меньшей из двух оценок.

Доступны три постановки:

- `xy-goal`: награда задаётся окрестностью физических координат цели;
- `state-goal`: используется представление конкретного полного состояния;
- `fixed-task`: одна официальная задача остаётся фиксированной для всех пар.

Эти величины различны; результаты разных режимов нельзя сравнивать как измерение одной и той же цели.

## Сравниваемые модели

| Модель | Вход | Что проверяет |
| --- | --- | --- |
| `xy` | Координаты старта и цели. | Достаточно ли положения на карте. |
| `full` | Полные состояния старта и цели. | Сколько даёт вся доступная информация. |
| `pose` | Состояния без двух пространственных координат. | Насколько информативны поза и скорости сами по себе. |
| `latent2` | Две обученные координаты на каждое состояние. | Достаточность двумерного представления. |
| `latent4` | Четыре обученные координаты на каждое состояние. | Пользу увеличения размерности. |

Модель полного состояния специально включает пространственный компонент и дополнительную поправку по полным признакам. Это снижает риск того, что большая модель проиграет только из-за переобучения на малой выборке.

## Быстрая проверка без чекпоинта

```powershell
python -m scripts.run_value_geometry `
  --synthetic `
  --quick `
  --output-dir artifacts/value_geometry_smoke
```

`--synthetic` создаёт искусственные данные, `--quick` уменьшает размеры обучения, `--output-dir` задаёт каталог результатов. Такая проверка подтверждает работоспособность конвейера, но не свойства настоящего агента.

## Основной эксперимент

```powershell
python -m scripts.run_value_geometry `
  --device cpu `
  --target-mode xy-goal `
  --max-states 18000 `
  --train-pairs 20000 `
  --goal-count 64 `
  --teacher-batch-size 128 `
  --models xy full latent2 latent4 `
  --model-seeds 0 1 2 `
  --epochs 80 `
  --output-dir artifacts/value_geometry_main
```

`--max-states` ограничивает исходные состояния; `--train-pairs` задаёт число пар; `--goal-count` — число целей; `--teacher-batch-size` — размер обращения к замороженному критику; `--models` перечисляет сравниваемые архитектуры; `--model-seeds` задаёт независимые начальные веса; `--epochs` ограничивает число проходов обучения.

Для фиксированной четвёртой задачи используйте `--target-mode fixed-task --task-id 4`. Если памяти мало, уменьшите `--teacher-batch-size` до `64`, `32` или `16`.

## Защита от утечки данных

1. Целые траектории сначала распределяются между обучением, промежуточной проверкой и итоговым тестом.
2. Пары строятся независимо внутри каждой части.
3. Тестовые цели не используются для обучения.
4. Восстановление физических координат обучается только на разрешённых обучающих состояниях.
5. Если используется карта, она применяется лишь для группировки по расстоянию вдоль коридоров, а не передаётся самой модели.

## Метрики

| Поле | Значение |
| --- | --- |
| `test_r2` | Какая часть разброса тестовых оценок объясняется моделью. |
| `test_rmse` | Среднеквадратичная ошибка предсказания. |
| `test_nrmse` | Ошибка, приведённая к масштабу целевой величины. |
| `far_r2` | Качество объяснения только для дальних пар. |
| `mean_spearman` | Насколько сохраняется относительный порядок кандидатов. |
| `top1_agreement` | Как часто совпадает лучший кандидат. |
| `mean_relative_regret` | Потеря качества при выборе подцели по вспомогательной модели. |
| `xy_readout_r2` | Насколько хорошо из обученного пространства восстанавливаются реальные координаты. |
| `xy_readout_p90` | Ошибка восстановления координат для 90% состояний. |

Низкое `R²` означает, что пространство не объясняет заметную часть изменчивости ценности. Даже хорошее восстановление FB-оценки не доказывает высокий реальный успех робота.

## Повторное обучение без вычисления F и B

```powershell
python -m scripts.run_value_geometry `
  --resume `
  --output-dir artifacts/value_geometry_main `
  --models xy full pose latent2 latent4 `
  --model-seeds 10 11 12 `
  --epochs 120
```

`--resume` переиспользует `pair_cache.npz`; чекпоинт и среда повторно не загружаются. Основные результаты сохраняются в `metrics.json`, `model_comparison.csv`, файлах предсказаний и графиках.

Проверка: `python -m unittest tests.test_value_geometry -v`.

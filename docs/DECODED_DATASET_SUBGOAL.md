# Проекция намерения на реальное офлайн-состояние

## Интуиция

Исходная высокоуровневая политика выдаёт намерение в 128-мерном пространстве, которое трудно интерпретировать. Вспомогательный декодер переводит это намерение в приблизительную точку `(x,y)`, после чего метод находит рядом реальное офлайн-состояние и использует намерение именно этого физически наблюдавшегося состояния.

## Мотивация

Декодированная точка сама по себе может быть неточной или попадать между состояниями обучающего набора. Привязка к реальному состоянию возвращает выбор в область известных примеров и позволяет дополнительно учесть оценку замороженного критика.

## Математика в трёх предложениях

Высокоуровневая политика предлагает `z_h`, а декодер вычисляет `q=D_xy(z_h)`. Среди реальных состояний `w`, удовлетворяющих `||xy(w)-q||≤R`, выбирается кандидат по осторожной FB-оценке `mean_e⟨F_e(s,z_w),z_r⟩-λ·range_e`, где `z_w=normalize(B(w))`. Исполняется именно `z_w`; координаты конечной цели не изменяются.

## Подробное правило выбора

$$
q=D_{xy}(z_h),\qquad
\mathcal C(q)=\{w:\|xy(w)-q\|_2\leq R\},
$$

$$
S(s,w)=\operatorname{mean}_e
\langle F_e(s,z_w),z_r\rangle
-\lambda\operatorname{range}_e
\langle F_e(s,z_w),z_r\rangle.
$$

Если внутри радиуса нет кандидатов, выбирается глобально ближайшее реальное состояние и этот резервный переход записывается в диагностику. Режим `nearest-xy` игнорирует оценку критика и служит отдельной контрольной проверкой.

## Варианты конечного намерения

| Значение `--finish-mode` | Что происходит |
| --- | --- |
| `task-latent` | Исходное представление задачи фиксировано на протяжении всего эпизода. |
| `fixed-v-max` | Полное состояние около цели выбирается один раз в начале. |
| `dynamic-v-max` | Полное состояние около цели перевыбирается при каждом перепланировании. |

Во всех вариантах положение конечной цели одинаково. Меняется только полное состояние, используемое для формирования условия высокоуровневой политики.

## Один официальный запуск

```powershell
python -m scripts.run_decoded_dataset_subgoal `
  --decoder artifacts/intention_xy_decoder_deep `
  --task-id 1 `
  --environment-seed 0 `
  --controller-seed 0 `
  --temperature 0 `
  --candidate-radius 0.5 `
  --max-candidates 64 `
  --disagreement-penalty 0.5 `
  --selection-mode max-v `
  --finish-mode task-latent `
  --replan-interval 1 `
  --results-dir results_decoded_dataset_subgoal
```

`--decoder` указывает готовую модель; `--candidate-radius` задаёт радиус `R`; `--max-candidates` ограничивает число сравниваемых состояний; `--disagreement-penalty` задаёт `λ`; `--selection-mode` выбирает оценку по критику или ближайшие координаты; `--finish-mode` определяет обработку цели; `--replan-interval` задаёт частоту перепланирования.

Чтобы задать собственные координаты, замените `--task-id 1` на `--start-xy 0 0 --goal-xy 4 4`. Координаты должны соответствовать карте в корневом README.

## Парная проверка геометрии и ценности

```powershell
foreach ($mode in @("nearest-xy", "max-v")) {
  foreach ($seed in 0..20) {
    python -m scripts.run_decoded_dataset_subgoal `
      --decoder artifacts/intention_xy_decoder_deep `
      --task-id 1 `
      --environment-seed $seed `
      --controller-seed 0 `
      --temperature 0 `
      --selection-mode $mode `
      --finish-mode task-latent `
      --replan-interval 1 `
      --results-dir "results_projection_$mode"

    if ($LASTEXITCODE -ne 0) {
      throw "Ошибка: режим=$mode, инициализация=$seed"
    }
  }
}
```

Метод улучшает выбор одной подцели, но не оценивает явную последовательность нескольких будущих намерений.

# Локальный H0: ближайшая подцель, прямой вариант и отдельный финиш

## Интуиция

Обычный H0 может выбрать первую подцель слишком далеко или продолжать сложное планирование, когда робот уже почти у цели. Этот вариант разрешает первую подцель только рядом с текущим состоянием, сравнивает план с прямым движением и у финиша переключается в отдельный устойчивый режим.

## Мотивация

Геометрически разумный путь не помогает, если первая команда физически слишком резкая или если робот начинает петлять возле цели. Поэтому планировщик разделяет три ситуации: прямое движение, маршрут через две промежуточные точки и завершение эпизода около финиша.

## Математика в трёх предложениях

Прямой вариант оценивается как `J₀ ≈ ⟨F(s,z_g),z_r⟩`. Маршрут через две точки использует формулу H0, но первая точка обязана удовлетворять `||xy(w₁)-xy(s)|| ≤ local_radius`, а вторая выбирается по всему офлайн-набору. Если робот попадает в `finish_radius`, маршрут больше не оптимизируется: управление передаётся выбранному финишному контроллеру.

## Подробная постановка

$$
J_2=V_1(s)
+\eta_1[V_2(w_1)-V_1(w_1)]
+\eta_1\eta_2[V_g(w_2)-V_2(w_2)],
$$

$$
\|xy(w_1)-xy(s)\|_2\leq R_{\mathrm{local}}.
$$

План с переключением используется только если его оценка превосходит прямой вариант с учётом `switch_margin`. Состояния второй точки выбираются равномернее по клеткам карты, чтобы несколько плотных участков офлайн-набора не вытеснили остальные коридоры.

После входа в финишную область по умолчанию режим фиксируется до конца эпизода. Это не доказанная оптимальная стратегия, а инженерная гипотеза, которую нужно проверять отдельными сравнениями.

## Один запуск

```powershell
python -m scripts.run_h0_local_terminal `
  --task-id 4 `
  --environment-seed 0 `
  --controller-seed 0 `
  --temperature 0 `
  --candidates-per-cell 10 `
  --grid-cell-size 4 `
  --local-radius 5 `
  --max-local-candidates 32 `
  --finish-radius 2 `
  --finish-mode direct `
  --direct-latent-mode raw `
  --pair-batch-size 512 `
  --results-dir results_h0_local_terminal
```

| Параметр | Смысл |
| --- | --- |
| `--candidates-per-cell` | Максимум реальных состояний из одной клетки. |
| `--grid-cell-size` | Размер клетки карты. |
| `--local-radius` | Радиус допустимой первой подцели. |
| `--max-local-candidates` | Максимум локальных первых подцелей. |
| `--finish-radius` | Радиус включения финишного режима. |
| `--finish-mode` | `direct` — прямое целевое намерение; `baseline` — исходный контроллер. |
| `--direct-latent-mode` | `raw` сохраняет исходный целевой вектор; `normalized` нормализует его. |
| `--pair-batch-size` | Число пар, оцениваемых за один блок. |

Общие параметры задают задачу, оба числа случайности, температуру и каталог результатов; полный список приведён в [CLI_PARAMETERS.md](CLI_PARAMETERS.md).

## Пять задач и 21 инициализация

```powershell
foreach ($taskId in 1..5) {
  foreach ($seed in 0..20) {
    python -m scripts.run_h0_local_terminal `
      --task-id $taskId `
      --environment-seed $seed `
      --controller-seed 0 `
      --temperature 0 `
      --candidates-per-cell 10 `
      --local-radius 5 `
      --max-local-candidates 32 `
      --finish-radius 2 `
      --pair-batch-size 512 `
      --results-dir results_h0_local_terminal_21

    if ($LASTEXITCODE -ne 0) {
      throw "Ошибка запуска: задача=$taskId, инициализация=$seed"
    }
  }
}
```

Далее выполните:

```powershell
python -m scripts.evaluate_results --results-dir results_h0_local_terminal_21
python -m scripts.summarize_h0_local_terminal --results-dir results_h0_local_terminal_21
python -m scripts.paired_analysis `
  --baseline-dir results_baseline_21 `
  --candidate-dir results_h0_local_terminal_21 `
  --output comparisons/h0_local_terminal_vs_baseline.json
```

Первая команда считает общие метрики, вторая разбирает падения и режимы контроллера, третья сопоставляет одинаковые эпизоды с исходным методом.

## Отдельные проверки влияния компонентов

- `--finish-radius 0` отключает отдельный финиш практически для всех состояний.
- `--no-zero-level` убирает сравнение с прямым вариантом.
- `--finish-mode baseline` использует у цели исходную высокоуровневую политику.
- `--no-finish-latch` разрешает выходить из финишного режима.
- `--switch-margin` требует дополнительного выигрыша оценки перед переключением.

Каждую конфигурацию сохраняйте в отдельный каталог. Диагностика траекторий содержит текущий режим, расстояние до цели, оценки прямого и двухточечного маршрута, количество кандидатов и выбранные координаты подцелей.

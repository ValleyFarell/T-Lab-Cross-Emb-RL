# Поправки на состояние робота в начале и конце маршрута

## Интуиция

Два робота в одинаковой точке карты могут иметь разную ориентацию, скорость и устойчивость. Один уверенно начнёт движение, другой может быть развёрнут неудобно или уже терять равновесие. Эксперимент проверяет, помогает ли отдельная поправка на такие свойства, когда пространственная часть маршрута уже оценена по координатам.

## Мотивация

Если геометрия описывает общий маршрут, а поза и скорость лишь повышают или понижают его осуществимость, удобнее оценивать эти эффекты отдельно. Но нужно проверить, действительно ли произведение поправок лучше простой модели по координатам, обычного сложения и модели по полному состоянию.

## Математика в трёх предложениях

Базовая пространственная модель вычисляет `H_xy(x_s,y_s,x_g,y_g)`. Дополнительные сети строят коэффициенты `A(u_s)` и `D(u_g)` по непространственным признакам старта и цели. Основная гипотеза имеет вид `Y(s,g) ≈ H_xy·A(u_s)·D(u_g)` и сравнивается с вариантами одной поправки, сложения и полного состояния.

## Сравниваемые модели

| Модель | Формула | Проверяемый вопрос |
| --- | --- | --- |
| `xy` | `H_xy` | Достаточно ли одних координат. |
| `xy_start` | `H_xy · A(u_s)` | Помогает ли качество начального состояния. |
| `xy_goal` | `H_xy · D(u_g)` | Помогает ли качество целевого состояния. |
| `xy_both` | `H_xy · A(u_s) · D(u_g)` | Полезны ли обе мультипликативные поправки. |
| `xy_additive` | `H_xy + A(u_s) + D(u_g)` | Не достаточно ли обычного сложения. |
| `full` | `H(s,g)` | Что даёт модель по полным состояниям. |

Все варианты получают одинаковые пары и одинаковое разделение данных. `F`, `B` и политики остаются замороженными.

## Какая величина предсказывается

При самостоятельном формировании данных:

$$
w_g=B(g),\qquad
z_g=\operatorname{normalize}(B(g)),
$$

$$
Y(s,g)=\min_e\langle F_e(s,z_g),w_g\rangle.
$$

Это оценка для конкретного полного целевого состояния. Она может отличаться от пространственной награды OGBench, где представление задачи строится по всем состояниям около целевых координат. Для прямого сравнения с экспериментом геометрии нужно переиспользовать именно его сохранённые пары через `--data-dir`.

## Проверка без настоящего агента

```powershell
python -m unittest tests.test_value_state_factors -v
python -m scripts.run_value_state_factors --synthetic --quick
```

`--synthetic` создаёт искусственный набор, а `--quick` уменьшает размер проверки. Эти команды проверяют реализацию, но не подтверждают гипотезу на настоящем лабиринте.

## Основной эксперимент

```powershell
python -m scripts.run_value_state_factors `
  --device cpu `
  --max-states 80000 `
  --train-pairs 160000 `
  --goal-count 384 `
  --candidates-per-start 8 `
  --models xy xy_start xy_goal xy_both xy_additive full `
  --model-seeds 0 1 2 `
  --epochs 100 `
  --patience 20 `
  --output-dir artifacts/value_state_factors
```

`--max-states` ограничивает число исходных состояний; `--train-pairs` — количество обучающих пар; `--goal-count` — число различных целей; `--candidates-per-start` — число целей на один старт. `--models` задаёт сравниваемые архитектуры, `--model-seeds` — независимые инициализации, `--epochs` — максимальное число проходов, `--patience` — ожидание улучшения перед ранней остановкой.

## Использование уже сохранённых пар

```powershell
python -m scripts.run_value_state_factors `
  --data-dir artifacts/value_geometry_large `
  --models xy xy_start xy_goal xy_both xy_additive full `
  --model-seeds 0 1 2 `
  --epochs 100 `
  --output-dir artifacts/value_state_factors_cached
```

Чтобы предварительно проверить названия и размеры массивов, добавьте `--inspect-cache`. Это полезно, если нужно подтвердить, что сравнивается та же целевая величина, что в предыдущем эксперименте.

## Результаты и ограничения

`metrics.json` содержит `R²`, ошибки, результаты по расстояниям, совпадение лучшей подцели и потери выбора. Также сохраняются график сравнения моделей, веса, предсказания, история обучения и `pairs.npz`.

Расстояния группируются по обычной евклидовой метрике `(x,y)`, а не по реальной длине коридоров. Поэтому две точки по разные стороны стены могут оказаться в одной группе «близких» состояний. Хорошая модель поправок описывает оценку замороженного критика, но не является самостоятельным доказательством лучшего управления.

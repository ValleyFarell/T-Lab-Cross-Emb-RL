# H0-B: одна или две промежуточные цели

## Интуиция

Иногда второй поворот улучшает маршрут, а иногда лишняя подцель только усложняет простой проход. H0-B оценивает оба варианта и выбирает глубину маршрута по результату сравнения.

## Мотивация

Дополнительное переключение должно использоваться только тогда, когда оно улучшает оценку плана. При равенстве оценок предпочтение отдаётся более простой цепочке через одну точку.

## Математика в трёх предложениях

Для одной подцели вычисляется `J₁ = V₁(s)+η₁[V_g(w₁)-V₁(w₁)]`. Для двух подцелей используется формула H0: `J₂ = V₁(s)+η₁[V₂(w₁)-V₁(w₁)]+η₁η₂[V_g(w₂)-V₂(w₂)]`. Если лучший `J₁` не меньше лучшего `J₂`, выбирается глубина один; иначе — глубина два.

## Подробное правило

$$
J_1^*=\max_w J_1(s,w),
\qquad
J_2^*=\max_{w_1,w_2}J_2(s,w_1,w_2).
$$

Каждый план глубины один явно помещается на диагональ матрицы планов глубины два:

$$
J_2(w,w):=J_1(w).
$$

Поэтому для **оценок модели** выполняется `J₂* ≥ J₁*`; при точном равенстве выбирается глубина один. Это не гарантирует рост реальной награды или доли успехов. Вариант без промежуточных точек данный метод не сравнивает.

## Запуск

```powershell
python -m scripts.run_h0b `
  --task-id 1 `
  --environment-seed 0 `
  --controller-seed 0 `
  --temperature 0 `
  --max-candidates 64 `
  --pair-batch-size 4096 `
  --h0-replan-interval 1 `
  --results-dir results_h0b
```

`--max-candidates` ограничивает количество состояний, `--pair-batch-size` — размер вычислительного блока, а `--h0-replan-interval` задаёт число шагов между перепланированиями. Остальные параметры определяют задачу, случайность, температуру и каталог результатов.

В `trajectory.npz` сохраняются выбранная глубина и лучшие оценки обоих вариантов. Сравнивать метод с H0 и исходным агентом нужно на одинаковых задачах и обоих значениях `seed`; см. [BASELINE_METRICS.md](BASELINE_METRICS.md).
